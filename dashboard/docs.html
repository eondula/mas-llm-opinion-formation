Current experiment setup

Opinion Lab studies context-conditioned stance between two strategies. Each agent has a checkpoint and a separate interaction history. Model weights remain unchanged throughout a conversation.

Run modes

Quick preview
One conversation with two agents sharing one checkpoint and one selected scenario. Uses the selected starting strategies, schedule, argument source and number of rounds. Study analyses and condition lists are excluded.
Study: selected conditions
With the paper suite unchecked, runs the selected agent count, checkpoint assignment and scenarios. Optional JSON conditions override initialization, schedule, argument_mode or presentation_order. Measurement checks and controlled histories can be enabled separately.
Paper suite for selected agents
Runs natural initialization and every forced strategy combination, all four schedules, both argument sources and both presentation orders. Enables validation, controlled histories, replay, sufficiency, prediction, component and head interventions, source-span interventions and continuation. This replaces the individual starting-strategy, schedule, argument-source, condition-list and analysis selections. The selected agent count, checkpoints, scenarios, rounds and token limit remain in use.

The dashboard suite does not automatically sweep agent counts or checkpoint assignments. The terminal preset studies/paper.json does: it currently specifies 3,168 main conversations across Sensor and Storage, two- and three-agent groups, and three checkpoints: Qwen2.5-1.5B-Instruct, Qwen2.5-3B-Instruct and HuggingFaceTB/SmolLM2-1.7B-Instruct. It includes all nine ordered two-agent pairs and all six three-agent assignments with three different checkpoints.

python -m llm_mas preview --scenario storage --rounds 3 --run-id preview_check
python -m llm_mas study --config studies/paper.json --dry-run
python -m llm_mas study --config studies/paper.json --run-id paper_study
python -m llm_mas dashboard

Experiment setup

Run ID
Optional name containing letters, digits, underscores or hyphens. Blank uses the current system date and time. Existing IDs cannot be overwritten. Saved runs can be inspected from the dashboard.
Agents and checkpoints
Study mode supports two or more agents. Enter one checkpoint per line: one entry shares weights across all agents; otherwise supply exactly one entry per agent, in Agent A, B, C order. This is an assignment within a conversation, not a list of independent experiments. Quick preview requires one entry.
Scenarios
Choose one scenario for preview or one or more for study. Each defines two candidates and argument pools. The scenario editor creates a new scenario from the selected template; it does not overwrite an existing ID.
Natural starting strategies
Each agent's initial choice follows its measured candidate likelihood margin before peer communication.
Forced starting strategies
Choose Strategy 1 or 2 for each agent at initialization. Only the starting strategy is assigned; subsequent choices use the decision-stage margin. The paper suite includes all four forced pairs or all eight forced triples, plus natural initialization.
Synchronous
Every agent receives the other agents' previous-round messages before responding.
Sequential, forward
Agents update A, B, C and onward. Later agents receive earlier agents' new messages within the same round; messages from agents that have not updated come from the previous round.
Sequential, reverse
Reverses the update order: B then A for two agents, C then B then A for three agents.
No peer control
Agents retain their own responses but receive no peer messages.
Arguments
Predefined arguments cycle through the selected strategy's pool. Generated arguments are produced by the model up to the token limit. Both modes use the selected canonical candidate statement in the public response.
Rounds
Interaction updates after round zero. A setting of 20 yields initialization plus 20 update rounds per agent.
Presentation order
The default presents Strategy 1 first. The paper suite uses both orders. A selected-condition JSON entry can set presentation_order to strategy_1_first or strategy_2_first.

Example conditions for a two-agent study with the paper suite unchecked:

[{"initialization":"natural","schedule":"synchronous"},
 {"initialization":[2,1],"schedule":"reverse_sequential"}]

Measurements and communication

Raw stance margin
Full-string conditional log-likelihood of candidate 1 minus candidate 2. Positive supports Strategy 1; negative supports Strategy 2. The raw margin is the principal effect-size quantity.
Displayed stance
The bounded score tanh(margin / 2), from −1 to +1. Charts show stance after the agent's own response. Decision-stage stance selects the public strategy and can differ from post-response stance. Agreement of public strategy with that decision score is built into the procedure.
Measurement timing
Records measurements before peer receipt, at decision, and after appending the public response. Forced initialization has no measured decision-stage choice.
Sentiment
Classifier-assessed valence of public text, scored after conversations and requested research analyses. It does not measure strategy support. Identical text has the same cached sentiment even when history-conditioned stance differs.
Agent display
Circle colors identify public strategies. Curved arrows show actual sender-to-receiver deliveries at the selected response. No-peer conditions have no delivery arrows. Click a message to read its full text.
Playback and progress
The slider and playback advance through recorded agent responses. Following live tracks the latest response. Elapsed time covers the run; ETA estimates the current phase when enough progress is available.

The score describes relative support under a specific model, prompt, history and candidate pair. It is not a calibrated probability or evidence of a persistent human-like belief.

Saved outputs

Outputs are stored under results/studies/<run_id>/. Each run saves configuration, input prompts and scenarios, task metadata, conversation records and status. Completed exports include transcripts, trajectory data, figures, CSV tables, selected LaTeX tables and an HTML figure index.

Study analysis outputs depend on the requested modules and eligible histories. The download ZIP contains exported figures and tables, including copied transcripts; complete raw measurement records remain in the run directory. Download links become usable after export finishes.

python -m llm_mas figures --run-id paper_study
python -m llm_mas resume --run-id paper_study

Resume reuses completed conversations and analysis modules when source and input checks match. Interrupted conversations or modules restart. Closing the browser does not stop a run; use Stop to interrupt it.

Current coverage

The terminal paper preset uses three different checkpoints in each three-agent conversation. For the same setup in the dashboard, enter these three checkpoint IDs on separate lines and select three agents. Group trajectory prediction currently covers two-agent conversations. There is no dedicated no-history conversation mode or persona experiment in this runner.

Measurement validation currently focuses on initial contexts. Label, speaker-name, formatting and transcript-placement checks are incomplete. Internal analyses sample selected events (one per conversation in the paper suite), and matched-history analyses may find no eligible match. Export availability does not establish scientific validity or complete research coverage. The full suite has not been validated end to end on real checkpoints.
